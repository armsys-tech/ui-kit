Publish events

Append one or more events to a stream. Events are durably stored, ordered per partition key and delivered to every active subscriber.

Stable Updated 24 Sep 2026 6 min read

#Overview

The publish endpoint accepts a batch of up to 500 events per request. Each event carries a type, an optional key used for ordering, and an arbitrary JSON payload. Requests are idempotent when an Idempotency-Key header is provided.

  • Events with the same key are delivered in the order they were accepted.
  • Payloads up to 256 KB are accepted; larger payloads should reference object storage.
    • Compression is applied automatically above 4 KB.
  • Accepted events are visible to subscribers in a median of 38 ms.
Batch for throughput

Sending 50–200 events per request typically maximises throughput while keeping tail latency low.

#Authentication

Authenticate with a project API key in the Authorization header. Keys are scoped; publishing requires the streams:write scope.

curl -X POST https://api.armsys.tech/v1/streams/orders/events \
  -H "Authorization: Bearer $ARMSYS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"events":[{"type":"order.created","key":"cus_42","payload":{"total":129.9}}]}'
const res = await fetch("https://api.armsys.tech/v1/streams/orders/events", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.ARMSYS_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ events: [{ type: "order.created", key: "cus_42", payload: { total: 129.9 } }] }),
});
import { Armsys, type PublishResult } from "@armsys/sdk";

const armsys = new Armsys({ apiKey: process.env.ARMSYS_KEY! });
const result: PublishResult = await armsys.streams.publish("orders", [
  { type: "order.created", key: "cus_42", payload: { total: 129.9 } },
]);

Keep keys server-side

Never ship a key with streams:write to browsers or mobile apps. Use short-lived publish tokens instead.

#Endpoint

POST https://api.armsys.tech/v1/streams/{stream_id}/events

#Path parameters

stream_idstringRequired

Identifier or slug of the target stream, for example orders or str_8KqP2.

#Headers

HeaderTypeDescription
AuthorizationstringBearer token with the streams:write scope. Required
Idempotency-KeystringUnique key (max 64 chars). Retries with the same key return the original result for 24 hours.
X-Armsys-RegionenumOverride the project region: eu, us or apac.

#Request body

eventsarray<Event>Required

Between 1 and 500 events to append atomically.

Event attributes
typestringRequired

Dot-separated event name such as order.created.

keystringOptional

Partition key. Events sharing a key are strictly ordered.

payloadobjectRequired

Arbitrary JSON, up to 256 KB after encoding.

deliveryenumOptionalDefault "standard"

Delivery class for this batch.

standardprioritybulk

#Responses

202Events accepted and queued for delivery.
400Malformed body or more than 500 events.
401Missing or invalid API key.
429Rate limit exceeded. Retry after the Retry-After header.
503Region temporarily unavailable; safe to retry with the same idempotency key.
JSON
{
  "accepted": 1,
  "stream": "orders",
  "events": [
    { "id": "evt_01J9Z6Q4N7", "offset": 884213, "partition": 3 }
  ],
  "duplicate": false,
  "region": "eu-central"
}
{
  "error": {
    "code": "rate_limited",
    "message": "Publish quota of 5000 events/s exceeded",
    "retry_after": 2
  }
}

#Subscribe over WebSocket

Consumers receive published events in real time by opening a WebSocket connection. Each message is a JSON envelope; acknowledge offsets to resume after reconnects.

WSS wss://rt.armsys.tech/v1/streams/{stream_id}/subscribe

  1. Open the connection

    Pass the API key as a token query parameter or in the first frame.

  2. Receive events

    Messages arrive as {"type":"event","offset":…}; heartbeats every 15 seconds.

  3. Acknowledge

    Send {"ack": offset} periodically to persist your position.

Terminal
$armsys streams tail orders --region eu
Connected to wss://rt.armsys.tech (eu-central) in 41 ms
14:02:11  order.created   cus_42   {"total":129.9}
14:02:12  order.paid      cus_42   {"method":"card"}

#Error handling

All errors share the same shape. Retry 429 and 5xx responses with exponential backoff; do not retry other 4xx responses without changing the request.

CodeMeaningRetry
invalid_requestBody failed validationNo
unauthorizedKey missing, revoked or lacks scopeNo
rate_limitedQuota exceeded for the current windowYes
unavailableTransient regional failureYes

Tip: the SDKs implement retries, backoff and idempotency keys for you.
